# 要件ドキュメント

## イントロダクション

家計簿アプリは、ユーザーが日々の支出を記録し、カテゴリ別に分類して視覚的に把握できるiOS/iPadOSアプリケーションです。複数の資金元（家計、お小遣い、銀行口座など）を管理し、家族やパートナーとデータを共有できる機能を提供します。SwiftUIとSwiftDataを使用し、Apple純正のフレームワークのみで実装します。

## 用語集

- **System**: 家計簿アプリケーション全体
- **User**: アプリを使用する個人ユーザー
- **Transaction**: 支出または収入の記録
- **Category**: 支出の大分類（例：食費、交通費）
- **Subcategory**: カテゴリ内の小分類（例：食費 → 食品、飲料）
- **Fund Source**: 資金元（家計、お小遣い、銀行口座など）
- **Account**: ユーザーアカウント
- **Shared Budget**: 複数アカウント間で共有される家計簿データ

## 要件

### 要件 1: 支出記録の作成

**ユーザーストーリー:** ユーザーとして、日々の支出を記録したい。そうすることで、お金の使い道を追跡できる。

#### 受入基準

1. システムは、金額、日付、カテゴリ、サブカテゴリ、資金元を含む新しい取引を作成するためのユーザーインターフェースを提供すること
2. ユーザーが取引を送信するとき、システムは金額が正の数であることを検証すること
3. ユーザーが取引を送信するとき、システムはカテゴリが選択されていることを検証すること
4. ユーザーが取引を送信するとき、システムは資金元が選択されていることを検証すること
5. ユーザーが取引を正常に送信したとき、システムはSwiftDataを使用して取引をローカルストレージに永続化すること

### 要件 2: カテゴリとサブカテゴリの管理

**ユーザーストーリー:** ユーザーとして、支出をカテゴリとサブカテゴリで分類したい。そうすることで、支出の内訳を詳細に把握できる。

#### 受入基準

1. システムは、食費、交通費、光熱費、娯楽費、医療費を含む事前定義されたカテゴリを提供すること
2. システムは、ユーザーが名前とオプションのアイコンを持つカスタムカテゴリを作成できるようにすること
3. カテゴリが作成されたとき、システムはユーザーがそのカテゴリの下に複数のサブカテゴリを定義できるようにすること
4. システムは、食費カテゴリに対して食品と飲料を含む事前定義されたサブカテゴリを提供すること
5. ユーザーが取引作成中にカテゴリを選択したとき、システムはそのカテゴリで利用可能なサブカテゴリを表示すること

### 要件 3: 資金元の管理

**ユーザーストーリー:** ユーザーとして、複数の資金元（家計、お小遣い、銀行口座）を登録したい。そうすることで、どの資金元から支出したかを記録できる。

#### 受入基準

1. システムは、ユーザーが名前と初期残高を持つ複数の資金元を作成できるようにすること
2. ユーザーが取引を作成するとき、システムはユーザーがどの資金元に取引が関連付けられているかを選択できるようにすること
3. 取引が作成されたとき、システムは取引金額を差し引いて関連する資金元の残高を更新すること
4. システムは、各資金元の現在の残高を表示すること
5. システムは、ユーザーが資金元の残高を手動で調整できるようにすること

### 要件 4: 月次・年次グラフ表示

**ユーザーストーリー:** ユーザーとして、月ごとや年ごとの支出をグラフで見たい。そうすることで、支出の傾向を視覚的に理解できる。

#### 受入基準

1. システムは、Apple Chartsフレームワークを使用して、当年の月別総支出を示すグラフを表示すること
2. システムは、選択された月のカテゴリ別支出内訳を示すグラフを表示すること
3. ユーザーがグラフ内のカテゴリを選択したとき、システムはサブカテゴリ別の内訳を表示すること
4. システムは、ユーザーが月次ビューと年次ビューを切り替えられるようにすること
5. システムは、選択された期間の総支出を計算して表示すること

### 要件 5: 複数アカウントでのデータ共有

**ユーザーストーリー:** ユーザーとして、家族やパートナーと家計簿データを共有したい。そうすることで、共同で家計を管理できる。

#### 受入基準

1. システムは、ユーザーが認証資格情報を持つアカウントを作成できるようにすること
2. システムは、ユーザーが特定の資金元を共有するために他のアカウントを招待できるようにすること
3. ユーザーが共有招待を受け入れたとき、システムは共有された資金元の取引をアカウント間で同期すること
4. システムは、ユーザーがどの資金元を各アカウントと共有するかを設定できるようにすること
5. 共有された資金元に対して取引が作成されたとき、システムはその資金元へのアクセス権を持つすべてのアカウントに取引を同期すること

### 要件 6: プラットフォーム対応

**ユーザーストーリー:** ユーザーとして、iPhoneとiPadの両方でアプリを使いたい。そうすることで、どのデバイスでも家計簿を管理できる。

#### 受入基準

1. システムは、iOS 17とiOS 18をサポートすること
2. システムは、縦向きのiPhoneとiPadデバイスをサポートすること
3. システムは、SwiftUIの適応型レイアウトを使用して、異なる画面サイズに合わせてユーザーインターフェースのレイアウトを調整すること
4. システムは、iPhoneとiPad全体で一貫した機能を維持すること
5. システムは、SwiftDataを使用して各デバイスにデータをローカルに永続化すること

### 要件 7: ローカライゼーション

**ユーザーストーリー:** ユーザーとして、日本語と英語でアプリを使いたい。そうすることで、自分の言語でアプリを利用できる。

#### 受入基準

1. システムは、すべてのユーザーインターフェーステキストを日本語と英語で提供すること
2. デバイスの言語が日本語に設定されているとき、システムはすべてのテキストを日本語で表示すること
3. デバイスの言語が英語に設定されているとき、システムはすべてのテキストを英語で表示すること
4. システムは、選択されたロケールに従って通貨金額をフォーマットすること
5. システムは、選択されたロケールに従って日付をフォーマットすること

### 要件 8: ダークモード対応

**ユーザーストーリー:** ユーザーとして、ダークモードでアプリを使いたい。そうすることで、暗い環境でも快適に使用できる。

#### 受入基準

1. システムは、ライトモードとダークモードの両方の外観をサポートすること
2. デバイスの外観がダークモードに設定されているとき、システムはすべてのユーザーインターフェース要素をダークモードの色で表示すること
3. システムは、ライトモードとダークモードの両方ですべてのテキストが読みやすいことを保証すること
4. システムは、現在の外観モードに自動的に適応するセマンティックカラーを使用すること
5. システムは、ライトモードとダークモードの両方でグラフが見やすいことを保証すること

### 要件 9: アクセシビリティ対応

**ユーザーストーリー:** ユーザーとして、VoiceOverやDynamic Typeを使ってアプリを操作したい。そうすることで、視覚に障害があっても家計簿を管理できる。

#### 受入基準

1. システムは、すべてのインタラクティブなユーザーインターフェース要素にVoiceOverラベルを提供すること
2. システムは、すべてのテキスト要素でDynamic Typeをサポートすること
3. ユーザーがDynamic Typeを使用してテキストサイズを大きくしたとき、システムは大きなテキストに対応するようにレイアウトを調整すること
4. システムは、すべてのテキストとインタラクティブ要素に対して十分な色のコントラスト比を提供すること
5. システムは、すべての機能がVoiceOverジェスチャーでアクセス可能であることを保証すること

### 要件 10: データの永続化

**ユーザーストーリー:** ユーザーとして、入力したデータが保存されることを期待する。そうすることで、アプリを閉じても後でデータを確認できる。

#### 受入基準

1. システムは、SwiftDataを使用してすべての取引、カテゴリ、サブカテゴリ、資金元を永続化すること
2. ユーザーがアプリを閉じて再度開いたとき、システムは以前に入力されたすべてのデータを復元すること
3. システムは、アプリの更新でデータモデルが変更されたときにデータ移行を処理すること
4. システムは、破損を防ぐためにデータ整合性チェックを提供すること
5. システムは、デバイス上にデータを安全に保存すること
